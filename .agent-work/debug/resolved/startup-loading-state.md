# 启动加载状态与账号刷新回归

## 已确认现象

- 启动时业务页面先以空账号数组渲染，约一秒后才显示真实账号。
- 新增加载态后，账号刷新测试出现旧额度覆盖新额度的稳定失败。

## 根因

`refreshAll()` 在同步阶段读取 `accounts === null`，而它由 `$effect` 直接调用。Svelte 5 会追踪被调用函数中的同步响应式读取，因此每次账号数据变化都会重新执行整个加载 effect。刷新接口写入新账号数据后，额外触发的 GET 请求会以测试中的旧数据覆盖刷新结果。

## 最小修复

- `App.svelte` 在后端健康检查成功前不挂载业务页面。
- `Accounts.svelte` 使用 `null` 区分“未加载”和真实空数组，并在首次加载时显示骨架。
- `refreshAll()` 不读取账号响应式状态，只负责请求和写入。
- 初始 `initialLoading` 保持为 `true`。
- 首次失败后的“重试”使用独立函数显式设置加载态，再调用 `refreshAll()`。

## 验证

- `cd frontend && npm test`：6 个测试文件、48 个测试全部通过。
- 测试覆盖后端启动中、启动失败重试、账号请求中、真实空数组、账号请求失败重试。
- 手动刷新测试确认 `/api/accounts` 只调用一次，刷新后的额度不会被旧 GET 结果覆盖。
