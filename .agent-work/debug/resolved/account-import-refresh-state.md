# 账号导入与刷新状态

## 根因

三个导入入口各自拼接异步调用，刷新请求没有自己的完整生命周期。页面在刷新真正完成前就移除标记；普通导入还在读取输入前清空了输入值，旧测试则完全没有挂载组件。

## 已实现

- `importing` 仅代表凭据导入请求，导入响应返回后立即结束。
- 用 Svelte 5 的响应式 `SvelteSet` 保存正在刷新的账号 ID，支持多个账号并发且互不影响。
- 粘贴导入、从 `~/.codex` 导入和覆盖导入统一调用 `completeImport`。
- 导入结果先显示在账号列表，再启动由 `refreshAccount` 自己负责成功、失败和清理的刷新任务。
- 刷新结果与刷新标记在同一状态批次更新，不会先消失标记再延迟显示数据。
- 增加独立的账号“刷新”按钮；刷新标记使用绝对定位，不改变额度三列布局。
- 用真实 `Accounts.svelte` 组件测试替换无效的局部数组测试。

## 验证

- `cd frontend && npx vitest run`：1 个测试文件、4 个测试全部通过。
- `cd frontend && npm run build`：构建成功。
- 构建仍报告原有 modal backdrop 点击元素的 Svelte 无障碍警告，本次未扩大范围处理。
